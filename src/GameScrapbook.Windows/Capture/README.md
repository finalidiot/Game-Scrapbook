# Capture implementation notes

The initial capture backend uses a single GDI desktop snapshot before any capture UI is displayed. Its supported test target is an ordinary windowed or borderless SDR game. Exclusive fullscreen, protected surfaces and HDR may produce an unavailable or inaccurate screenshot and are not advertised as verified.

The source display comes from the physical mouse location at capture time using `MonitorFromPoint`. Focus return is resolved separately: prefer an existing external foreground window, or an external root window under the pointer when the scrapbook is selected. Captures without an external focus target remain valid. Selection, crop and drag coordinates remain physical pixels, including negative monitor origins. WPF overlays are positioned with `SetWindowPos`; the board alone converts the physical drop point into its own coordinates. Application manifest DPI awareness must be PerMonitorV2.

The optional `CanBeginCapture` host gate prevents a new operation during modal settings, readonly recovery or an existing card drag. An already-active capture is always cancellable with the capture shortcut even while that gate is closed. Own-app foreground no longer blocks capture. A minimized board is restored through `SW_SHOWNOACTIVATE` after taking the screenshot. The host's visible Snip button calls `BeginCapture()` after its countdown; `IsHotkeyRegistered` and `CaptureError` drive persistent availability/error UI.

Overlay presentation begins at zero opacity with nonempty dimensions, applies passive styles before show, sets physical bounds, updates layout, checks native/rendered size and DPI, then reveals the image. Tiny intermediate layouts do not create negative-size hint rectangles. Capture lifecycle diagnostics distinguish hotkey registration/delivery, screen selection, snapshot acquisition, overlay geometry and completion; no window titles or screen contents are logged.

The selection window has `WS_EX_NOACTIVATE` before showing and handles `WM_MOUSEACTIVATE`. The drag image is also click-through and its HWND is disabled, so `WindowFromPoint` ignores it for board hit-testing. A 12ms dispatcher timer reads current physical button state and `GetPhysicalCursorPos` only while a capture is active, so a release on the second screen does not depend on an unfocused WPF window receiving captured mouse events. Escape is registered as a temporary global hotkey to intercept ordinary Escape messages during the operation. If that registration is unavailable, session polling provides cancellation but the foreground game may also receive Escape. Button mapping respects the left-handed mouse setting. The game may still consume raw input; actual game testing is required. No injection or input-blocking driver is used.

The drop cursor marks the new card's upper-left. The host returns `CaptureDropTarget.BoardPosition` in board coordinates and may supply `DisplayScale` (physical pixels per board unit) for a preview that matches board zoom and monitor DPI. Both host and preview use initial image dimensions capped at 520 by 420 board units, preserving aspect ratio and never enlarging a small capture.

A successful drop calls the host once. If the host throws while saving, the selected crop stays available for another attempt. An invalid target never auto-places the image. Normal focus restoration makes at most one `SetForegroundWindow` call and checks the actual foreground HWND. It avoids stolen focus after an intentional application switch and does not simulate clicks, Alt presses or repeated focus attempts. Cursor return is optional; a game can independently confine its own cursor.

Any existing cursor clipping is released once for the session. Its original bounds are restored only when the original source still owns foreground focus and no other application has installed new clip bounds. Games which immediately re-confine the pointer need game-specific testing; this implementation does not repeatedly fight their input management.

Every completion, cancellation, host-save error, exception and disposal path removes its windows and stops the capture timer as appropriate. Long-lived hotkeys are unregistered on disposal; changing a hotkey registers its replacement first so a conflict leaves the previous binding usable.
